# 0003 データ構造の簡素化

- 日付：2026-11-15
- 状態：決定（0001 の一部を置き換える）
- きっかけ：ユーザーの依頼「シンプルであることと可用性（後から AI などで読み込んだり再構成したりできる）を最重要視して再レビュー。フォルダの過度な階層化は避ける」。Opus と Fable が別々にレビューし、ユーザーが「すべて採用」を選んだ

## 決めたこと

骨格（ドライブの Markdown が正本、D1 は作り直せる索引、`pages/` は階層なし、型の正本はコードの台帳）は 0001 のまま。**これから足す予定のものを減らす。**

1. **ドライブには `pages/`・`assets/`・`README.md` だけを置く。** 0001 の `_meta/manifest.json` と `_meta/schema.json` はやめる。`README.md` はプロジェクト直下に 1 枚、台帳から自動で作り、サーバーだけが書く。中身：frontmatter に `format: 1`（形式の版はこの 1 つの数字だけ）、本文に書き方の決まり（予約項目、日付・金額、リンク・タグ・query ブロックの文法、題名の同一視）と型の一覧表
2. **予約項目は `id`・`type`・`tags`・`created_at` の 4 つ。** `updated_at`・`updated_by` は持たない（部屋が 3 秒おきに書き出すたびに変わり、差分と競合の元になる。更新日時はドライブと索引で足りる）。外部 ID は入れ子にせず平らに書く（例：`gcal_id`）
3. **frontmatter の値は「文字・数・真偽、またはそのリスト」だけ。** 入れ子のオブジェクトは使わない（props のマージはキー単位なので、入れ子は同期どうしで丸ごと上書きし合う）
4. **書き出しの形を固定する。** 項目の順番は「予約項目、残りは名前順」。長い文字列を自動で折り返さない。日付は `YYYY-MM-DD`、時刻は `+09:00` 付き。数字だけの文字列（郵便番号など）は引用符を付ける
5. **題名は NFC に正規化して比べ、書く。** 80 文字まで。同一視は「空白と `_`、大文字小文字」
6. **型付きの記録も `pages/` に置き、題名の決まりで並べる**（例：`2026-11-15 食費 イオン.md`）。0001 の逃げ道 `records/<id>.md` は採らない
7. **D1 を最小にする。**
   - 索引は 1 表だけ（`pages`：project_id, id, path, title, type, props の JSON, links の JSON, revision）。リンク専用の表は作らない
   - 操作の記録（0001 の K）は、API トークンで外から書けるようになるまで作らない。作るときは「運営データ、保持 90 日」とする
   - API トークンは新しい表を作らず、`sessions` に種類と名前の列を足して兼ねる。値はハッシュで保存する
   - `apps/api/schema.sql` は消し、定義を 1 か所にする（0002 の migration）
8. **「全部を 1 つにまとめた書き出し」（zip か JSONL、その都度生成、ドライブには置かない）を早めに作る。** バックアップ・移行・外の AI への読み込みを兼ねる。移行を流す前には必ずこれを取る
9. **作る順番を変える。** ① 今のコードを丈夫にする（frontmatter の失敗を受け止める、props のリンク、改名をドライブの「名前の変更」で行う、NFC、書き出しの形） → ② `id` と `README.md` → ③ まとめた書き出しと取り込み → ④ 索引 → ⑤ Command → ⑥ トークンと REST → ⑦ MCP。①〜③で「アプリが無くなっても読める・移せる」状態になる。④以降は必要が出てから
10. **ファイルに書く Query の記法は 1 つにする。** JSON は API の中だけで使う

## 0001 から置き換えたもの

- 原則 3 の置き場（`_meta/` → `README.md`）
- 予約項目（7 つ → 4 つ）と `actor` を Page に残す方法（`updated_by` をやめ、記録は D1 の操作の記録だけ。それも外から書けるようになってから）
- K（変更履歴）：操作の記録は後回し。取り消しはドライブの版履歴とゴミ箱
- F の逃げ道（`records/<id>.md`）
- 「次の一手」の順番

## リスクと対策

- **アプリ以外が作ったファイルは見えない**（`drive.file` スコープ）：外の AI がドライブに直接 `.md` を置いても、アプリには現れない。`README.md` に「読む・直すは直接でよい、新しく作るのはアプリか API から」と書く。`id` の無いファイルや重複した `id` は、見つけたときに振り直す
- **管理者 1 人への依存**：OAuth 同意画面が「テスト」のままだと、ドライブの鍵が 7 日で切れる（未確認。本番公開にする）。鍵が切れたら「管理者がもう一度ログイン」と画面に出す。フォルダを家族のもう 1 人に閲覧で共有しておく。管理者の交代は、まとめた書き出しから取り込む
- **同名ファイル**：ドライブは同じフォルダに同名を許し、条件付き更新がない。一覧で同名を見つけたら警告して番号を付ける。開いているページへの書き込みは部屋に任せる
- **他の YAML 読み取りとの違い**：`yes`、日付、`0123` を別の型で読む道具がある。4 の書き出しの決まりで避ける
- **画像の容量**：今は 1 枚 10MB まで縮小なしで保存している。長辺 2000px 程度に縮めてから保存する（別の PR）
